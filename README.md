# Minecraft × ULTRAKILL

An unofficial **C# BepInEx gameplay mod**, not a standalone game, texture pack or JAR.

**Status: compiled 0.1.0 release candidate; in-game verification is outstanding.** This repository started empty apart from its README. The development sandbox has no Steam/ULTRAKILL installation or Unity runtime. The DLL compiles against real public reference assemblies, but loading, enemy combat, physics and scene behaviour have **not been tested in the game**. Do not mistake compilation or the policy tests for proof of playability on your particular Steam build.

## Implemented systems

- F switches between V1 and a separate procedural Steve body/viewmodel, retaining the existing player, Rigidbody and camera. Switching snapshots native weapon/arm visibility, controller enabled state, weapon HUD icons, movement speed and ability flags. Rollback restores these on failure, death and cleanup; no enemy or level reset.
- Original cubic Steve head, torso, articulated arms/legs, turquoise shirt, blue trousers, face and hair; procedural walking, mining and sword/axe swings. F5 toggles a collision-aware shoulder view using the **same camera**, showing the world body and held tool.
- Eight pixel-textured blocks: grass, dirt, stone, cobblestone, oak planks, glass, TNT and bedrock. Scene objects have static `BoxCollider`s, consistent grid positions, surface targeting, valid/invalid preview with on-screen reasons, outward snapping on non-grid-aligned surfaces, exact six-face adjacency on existing blocks, occupied-space checks, and a configurable count limit. Blocks default to the actual floor collider layer rather than assuming the game collision matrix.
- Held primary input mines blocks with progress, per-material hardness and axe wood bonus. Bedrock cannot be mined or destroyed by mod TNT.
- Nine-slot creative hotbar, icons, number keys and scrolling; E opens the palette to put **any of the eight blocks** into a building slot. Unlimited blocks, not a survival crafting/inventory economy.
- Diamond sword and axe: first/world-view voxel models, timed swings, independent cooldown/damage values, real `EnemyIdentifier.DeliverDamage`, limb identifier resolution, per-swing deduplication and wall occlusion. Hit marker plus the game's native damage effects.
- R ignites targeted TNT; flashing fuse, bounded explosion visual, native enemy/player damage, line-of-sight checks, dynamic Rigidbody force, eligible-block destruction and delayed TNT chains.
- Optional validated JSON layout saves separate from vanilla saves; per scene/grid, atomic replacement/backup, loaded-cell collision checks, unload cleanup and retained layout data across Unity object destruction.
- BepInEx config, bounded diagnostics, API compatibility checks and scoped Harmony ability patches.

These descriptions are implemented code paths, **not successful in-game test results**. See [architecture](docs/ARCHITECTURE.md) for API provenance and [test checklist](docs/TESTING.md) for the release gate.

For a hands-on installation and first-block walkthrough, see [Try building inside ULTRAKILL](docs/BUILDING.md).

## Install (Windows Steam, Mono build)

1. Back up your mod setup. Use a clean mod profile first; do not overwrite any game executable.
2. Install **BepInEx 5 x64** for ULTRAKILL (recommended official 5.4.23.2; compiled against 5.4.21). Launch once to create `BepInEx/plugins`, `BepInEx/config` and the log. Do not install BepInEx 6/IL2CPP for this DLL.
3. Extract `MinecraftUltrakill-0.1.0.zip` into the ULTRAKILL directory containing `ULTRAKILL.exe`. The DLL belongs at:
   ```text
   <SteamLibrary>/steamapps/common/ULTRAKILL/
     BepInEx/plugins/MinecraftUltrakill/MinecraftUltrakill.dll
   ```
4. No separate textures, bundles, game assemblies, Harmony or Unity DLLs should be copied alongside this mod. All original art is generated by the plugin; BepInEx supplies Harmony.
5. Launch a normal campaign level. Check `BepInEx/LogOutput.log` for `Runtime API verified` and `initialized`. If initialization fails, the plugin leaves V1 untouched; send the exact error and Steam build ID rather than forcing an unsupported signature.
6. Press F while active and not sliding/dashing/riding a rocket. **F conflicts with the default vanilla punch binding**; remap vanilla punch or the mod's switch key in its config. Settings are generated at `BepInEx/config/benluvzbacon.minecraft.ultrakill.cfg`.

Uninstall with the game closed: remove `BepInEx/plugins/MinecraftUltrakill`. Optional mod configs/layouts can be removed separately. Vanilla saves and executables are never altered.

## Controls in Steve mode

| Control | Action |
|---|---|
| F (configurable) | Switch V1 / Steve |
| WASD, mouse, jump | Existing game movement/camera, slower walking; no dash/slide/slam/wall jump |
| 1–9 / wheel | Hotbar selection (seven building slots, sword, axe) |
| E, then 1–8 | Block palette; assign grass/dirt/stone/cobble/oak/glass/TNT/bedrock |
| Primary fire / left mouse | Mine targeted mod block; otherwise swing selected sword/axe |
| Secondary fire / right mouse | Place selected building block; hold to repeat at a bounded rate |
| R | Ignite targeted TNT |
| F5 | Steve first-person / third-person shoulder view |

Fire input uses the game's `InputManager.InputSource` when available, so normal fire rebinding is respected. Configurable keys use New Blood's `LegacyInput` on current builds, falling back to Unity legacy input on older builds. Menu/pause input is gated. Steve does not craft, drop items, crouch with Minecraft rules or replace ULTRAKILL's gravity/jump physics. This intentional controller reuse avoids duplicate physics/input/camera instances.

## Build from a clean checkout

Requirements: **.NET SDK 8**, Python 3, internet access to NuGet and `nuget.bepinex.dev`. No installed game is required for the public-reference build.

```bash
bash scripts/build.sh
```

Windows PowerShell:

```powershell
./scripts/build.ps1
```

The scripts run policy tests, restore packages, build with warnings as errors, package only our DLL/docs, and validate PE/CLI/archive layout. Direct build:

```bash
dotnet build src/MinecraftUltrakill/MinecraftUltrakill.csproj -c Release -warnaserror
```

Outputs:
- `src/MinecraftUltrakill/bin/Release/net472/MinecraftUltrakill.dll`
- `release/MinecraftUltrakill-0.1.0.zip`

To compile against **your own installed Unity/BepInEx references** (still no Assembly-CSharp dependency):

```powershell
./scripts/build.ps1 `
  -GameManagedDir "C:/Program Files (x86)/Steam/steamapps/common/ULTRAKILL/ULTRAKILL_Data/Managed" `
  -BepInExCoreDir "C:/Program Files (x86)/Steam/steamapps/common/ULTRAKILL/BepInEx/core"
```

Never commit these reference assemblies. CI uses pinned public BepInEx.Core 5.4.21, HarmonyX 2.9.0 and UnityEngine.Modules 2022.3.29 compile packages. See [build evidence](docs/BUILD-EVIDENCE.md) for the distinct restricted-sandbox compiler path actually run here.

## GitHub Actions downloads

Workflow: [`.github/workflows/build.yml`](.github/workflows/build.yml), **Build mod**. It runs on pushes, PRs or manual dispatch. After the changes are pushed to GitHub, open **Actions → Build mod → successful run → Artifacts → MinecraftUltrakill-0.1.0**. Unzip the artifact wrapper, then extract the contained mod ZIP into ULTRAKILL. The SHA256 file verifies the mod ZIP. Workflow artifacts are not GitHub releases. The code is now pushed to the session branch. [Pull request #1](https://github.com/benluvzbacon/Minecraft-inside-ultrakill/pull/1) contains the changes; the default `main` branch remains unchanged until that PR is merged. The first [SDK 8 build run](https://github.com/benluvzbacon/Minecraft-inside-ultrakill/actions/runs/38382306911) passed and published the artifact. For newer building changes, download the artifact from the latest successful run on `arena/f80938d1-minecraft-inside-ultrakill`.

## Compatibility / remaining work

- Exact installed/current Steam APIs cannot be verified here. The runtime gate checks mandatory fields/signatures. Public mod evidence is historical, not a blanket current-version guarantee.
- **All in-game tests remain open**, including repeated switching, deaths, multiple enemy classes/bosses, animation/camera scale, special rooms, unusual geometry, save reloads and mod conflicts. See [TESTING.md](docs/TESTING.md).
- Bedrock is a real stationary physics collider, not a fake obstruction. Objects only stop if their real collision layers/physics support it. Scripted trains, teleports, animation-driven movers and navmesh-only enemies can ignore colliders. No train-specific compatibility patch or dynamic navmesh bake is claimed.
- New levels/custom maps/additive scenes, controllers/VR, custom player mods and different weapon/movement mods are untested. Campaign-only is the initial target.
- All art is original procedural voxel art, not exact copyrighted Minecraft textures. Audio, a survival inventory, crafting, block drops, imported skeletal animations and specialized boss damage patches are not provided.
- Saves store creative layouts, not live TNT fuse time; TNT reloads unprimed. Grid changes should occur with the game closed/between levels.
