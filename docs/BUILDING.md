# Try building inside ULTRAKILL

This is a real BepInEx C# plugin that creates blocks with `MeshRenderer` and `BoxCollider` components in the current game scene. It is not a browser demo. Its clean-checkout GitHub build passes, but the developer environment cannot run ULTRAKILL; the steps below are the **in-game test**, not a claim that it has already passed.

## Find the code and download

- The code is on `arena/f80938d1-minecraft-inside-ultrakill`, not yet on the default `main` branch.
- Open [pull request #1](https://github.com/benluvzbacon/Minecraft-inside-ultrakill/pull/1) or select that branch in GitHub's branch picker.
- Open **Actions → Build mod → latest successful run on that branch → Artifacts → MinecraftUltrakill-0.1.0**. Unzip that artifact download. It contains the actual mod ZIP and its SHA256 checksum.
- The building-refinement source at commit `3099263` passed [run 38382778913](https://github.com/benluvzbacon/Minecraft-inside-ultrakill/actions/runs/38382778913): **290 policy assertions**, mod compilation, packaging/PE validation and artifact publication. These are not in-game tests.

## Install

1. In Steam, right-click ULTRAKILL → Manage → Browse local files.
2. Use BepInEx **5 x64 / Mono**, recommended 5.4.23.2. Launch once to create its directories. Do not use BepInEx 6 or an IL2CPP build with this plugin.
3. Extract the **inner** `MinecraftUltrakill-0.1.0.zip` into the folder containing `ULTRAKILL.exe`.
4. Verify the resulting path:
   ```text
   ULTRAKILL/BepInEx/plugins/MinecraftUltrakill/MinecraftUltrakill.dll
   ```
5. Do not copy Unity/game/reference DLLs into the plugins folder. All textures/models are generated by our own code.

## Place your first blocks

1. Load an ordinary campaign level and close menus/terminals.
2. Remap the game's default F punch binding, or change the mod's switch key. The switch key defaults to **F**.
3. Press F to enter Steve. Finish any dash/slide/rocket ride first.
4. Press **1** for the grass-block slot. Aim at the floor within six units. A green preview means valid; an orange message/red preview explains a rejected cell.
5. **Right-click** to place. **Hold right-click** to continue placing, at most once per configured interval (default 0.2 seconds). A fresh right-click is required after switching characters, selecting a different slot/block, or opening the palette.
6. Aim at a placed block's top/side/bottom face to place an exact neighboring cube. Blocks have real stationary colliders; try walking onto a short stack.
7. **Hold left-click** to mine mod-created blocks. Watch the mining progress. This does not mine or delete original level geometry.
8. Press **E**, then **1–8**, to put grass/dirt/stone/cobble/oak/glass/TNT/bedrock into the selected building slot. Bedrock is choice **8** in this palette, not hotbar slot 8 (which is the sword).
9. Press F to return to V1. Blocks stay in that level and are removed on scene cleanup; optional save persistence can be enabled separately.

## Placement settings and troubleshooting

The generated config is `BepInEx/config/benluvzbacon.minecraft.ultrakill.cfg`. Edit with the game closed.

- `PlacementDistance`, `GridSize`, `MaxBlocks`, `HoldToPlace`, `PlacementInterval` and `MiningSpeed` control building.
- `BlockCollisionLayer = -1` uses the detected solid floor layer; it never changes the game's global collision matrix. The log prints the selected layer.
- If that layer ignores the player, the mod **rejects placement** instead of silently allowing pass-through blocks. Override the layer with the actual solid-floor layer number from your game/mod setup; do not guess or change global collision settings.
- Non-grid-aligned surfaces snap outward, so a small gap can remain. Complex/sloped geometry is still checked for overlap and can reject placements.
- Physics movers/enemies and occupied player space are rejected as placement targets.
- Existing level scripts, navmesh agents or scripted trains may ignore physical colliders. Train obstruction has not been tested or certified.

If F does nothing, no preview appears, or blocks do not collide: send the Steam build ID, the exact level, your config, and `BepInEx/LogOutput.log` after reproducing it. Look for the `Runtime API verified` and `initialized` messages. A missing loader/API must be diagnosed from the actual installation; a successful DLL build is not proof it loaded.
